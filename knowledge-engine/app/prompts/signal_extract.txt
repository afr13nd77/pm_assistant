Контекст компании:
{business_context}

Аналитический отчёт:
{report_content}

На основании отчёта извлеки actionable сигналы -- выводы, которые ведут к конкретной задаче в продуктовом бэклоге.

## Зона ответственности

Твой scope -- продуктовый бэклог Суточно.ру: фичи, эксперименты, улучшения, которые может реализовать продуктовая команда за 1-3 месяца.

НЕ извлекай:
- Стратегические угрозы уровня CEO/CPO (экзистенциальные риски рынка, доли рынка)
- Задачи для DevOps, Security, Marketing, Legal (мониторинг уязвимостей, PR-акции, юридические риски)
- Общеотраслевые тренды без конкретной привязки к бэклогу ("рост гибридных моделей", "смещение инвестиций")
- Реактивные одноразовые возможности ("воспользоваться сбоем конкурента", "перехватить пользователей")

## Правила извлечения

1. Каждый сигнал ОБЯЗАН содержать draft_idea с конкретным действием. Нет действия -- нет сигнала.
2. Максимум 1-3 сигнала. Качество важнее количества.
3. Каждый сигнал должен предлагать РАЗНОЕ действие для РАЗНОГО компонента продукта. Если два вывода ведут к одной фиче -- оставь один с более конкретной формулировкой.
4. title начинается с глагола действия ("Добавить...", "Внедрить...", "Запустить...", "Протестировать..."), а не с описания тренда.
5. В draft_idea.solution указывай конкретный компонент/экран/API Суточно.ру. Не пиши "изучить", "рассмотреть", "мониторить".

Верни ТОЛЬКО JSON (без markdown, без комментариев):
{
  "signals": [
    {
      "title": "<глагол + конкретный объект, напр. 'Добавить AI-теги активностей в карточку объекта'>",
      "analysis": "<3-5 предложений: что произошло, почему важно для бэклога>",
      "threat_level": "low" | "medium" | "high",
      "recommended_action": "<одно конкретное действие с указанием компонента системы>",
      "draft_idea": {
        "title": "<глагол + объект, напр. 'Внедрить explainable AI ranking в поисковую выдачу'>",
        "problem": "<измеримая боль пользователя или бизнеса>",
        "solution": "<что сделать + какой компонент затронут>",
        "domain": "<один из: static-metadata, search-engine, suggester, general, partner-search-engine>"
      },
      "domain": "<один из: static-metadata, search-engine, suggester, general, partner-search-engine>",
      "priority_hint": "high" | "medium" | "low",
      "rationale": "<почему этот сигнал важен, ссылка на конкретный факт из отчёта>"
    }
  ],
  "no_signals_reason": "<если actionable сигналов нет -- почему; это нормальный результат для информационных отчётов>"
}

Если в отчёте нет выводов, ведущих к конкретной задаче -- верни пустой массив signals и заполни no_signals_reason. Это лучше, чем сигнал без действия.
