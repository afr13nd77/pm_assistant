# CONTEXT.md — История проектирования PM Bot

Этот файл содержит контекст диалога, в котором был спроектирован и собран pm-bot.
Предназначен для Claude Code, чтобы понимать решения и их обоснование.

---

## Кто я

Продакт-менеджер OTA-компании (онлайн-бронирование отелей, квартир, апартаментов).
Отвечаю за **подсистему контента** — хранилище статической информации об объектах размещения.

**Мои задачи:**
- Генерация идей по развитию продукта
- Написание PRD в Confluence
- Ведение бэклога, постановка задач в Jira
- Формирование планов работ и контроль выполнения
- Анализ рынка и конкурентов
- Подбор источников данных для обогащения контента
- Проведение дейли и совещаний

**Моя боль:**
Информация размазана по Notion/Confluence, голове, Telegram, Obsidian. Нет единой точки сборки. Идеи теряются. Рутина (заметки с встреч, формулировка тикетов) отнимает время.

---

## Принятая концепция

**Подход Карпати (agentic engineering):** я выступаю надзором и оценщиком качества, агенты делают рутинные трансформации информации. Суждение, приоритизация, контекст продукта — мои. PRD, структурирование заметок, черновики Jira-тикетов, саммари с дейли — агентов.

**Obsidian как личный штаб:** не замена Confluence и Jira, а мой личный инструмент мышления. Корпоративные инструменты остаются для команды.

## Три автоматизированных потока (реализованы)

### Поток 1 — Захват идей
```
Telegram (текст) → Claude API → структурированная заметка → Obsidian/Inbox/
```
- Триггер: любое текстовое сообщение боту
- Команда: `/idea` (явный режим) или просто текст (режим по умолчанию)
- Выход: `YYYY-MM-DD-<slug>.md` с frontmatter, тегами, next steps

### Поток 2 — Заметки встреч
```
Транскрипт .txt (Яндекс Телемост) → drop в папку → watchdog → Claude API → Obsidian/Meetings/
```
- Триггер: появление `.txt` файла в папке `TRANSCRIPTS_INBOX`
- Автоматический, без участия человека
- Выход: `YYYY-MM-DD-<имя файла>.md` с решениями, action items, блокерами
- Оригинал переименовывается с суффиксом `.processed`

### Поток 3 — Черновики Jira-тикетов
```
Telegram (описание задачи) → Claude API → структурированный тикет → Obsidian/Tasks/Drafts/
```
- Триггер: команда `/jira` + текст
- Выход: `YYYY-MM-DD-jira-01.md` с Summary, Description, AC, Story Points
- Публикация в Jira — вручную (API корпоративный, доступ не подтверждён)

## Переменные окружения (.env)


**Важно:** Pro/Max подписка Claude Code НЕ покрывает прямые API-вызовы из кода.

## Структура папок в Obsidian vault

```
<VAULT_PATH>/
├── Inbox/          ← идеи из Telegram (поток 1)
├── Meetings/       ← заметки встреч из транскриптов (поток 2)
└── Tasks/
    └── Drafts/     ← черновики Jira-тикетов (поток 3)
```

Obsidian Cowork-проект не конфликтует — он работает со своей зоной vault'а,
новые скрипты пишут только в Inbox/, Meetings/, Tasks/Drafts/.

## Известные проблемы и решения

| Проблема | Решение |
|---|---|
| `anthropic==0.34.0` конфликтует с httpx: `unexpected keyword argument 'proxies'` | Обновить до `anthropic>=0.40.0` и пересобрать с `--no-cache` |
| Windows-пути в VAULT_PATH | Использовать прямые слеши: `C:/Users/...` |
| ALLOWED_CHAT_ID неизвестен | Запустить бота, написать `/start` — он ответит chat_id |

## Поток 4 — Еженедельный отчёт (запланирован, не реализован)

### Концепция
Каждый понедельник агент автоматически собирает отчёт «сделано за прошлую неделю / запланировано на текущую» и присылает в Telegram. Плюс команда `/report` для запроса в любой момент.

### Реализация: А+Б
**А — автоматический запуск:** APScheduler внутри Docker-контейнера, каждый понедельник в 09:00.
**Б — ручной запуск:** команда `/report` в Telegram-боте.

### Источники данных
- `Meetings/` — дейли и синки за прошлую неделю (решения, закрытые action items)
- `Tasks/Drafts/` — что было поставлено в Jira
- `Inbox/` — идеи, которые превратились в задачи
- Jira API — статусы тикетов (если доступен, иначе пропускается)

### Новые компоненты (к реализации)
- `app/reporter.py` — сбор данных из vault + генерация отчёта
- `app/scheduler.py` — APScheduler, понедельник 09:00
- Новая зависимость: `apscheduler==3.10.4`
- Новая команда бота: `/report`

## Идеи по развитию борда и системы (от реальных до безумных)

### Реалистичные
- **Morning sync** — борд как стартовая страница рабочего дня: транскрипты дейли уже обработаны, action items извлечены, приоритеты видны без открытия Confluence
- **Идея в лифте** — мобильный capture: вбил в терминал → агент обогатил пока шёл по коридору → к ноутбуку уже структурированная заметка
- **Конкурентный разведчик** — зафиксировал новость о конкуренте → агент автоматически связал с кластером конкурентного анализа
- **Jira без боли** — получил задачу в чате → вставил в TASK → через 10 сек готовый тикет с AC → скопировал в Jira
- **Борд как стенд-ап скрипт** — перед дейли открываешь Processing, зачитываешь карточки команде, без "что я делал вчера"
- **Ретроспектива через синтез** — в конце спринта SYNTHESIZE_INBOX группирует все идеи за 2 недели, выявляет паттерны, выдаёт топ тем
- **Дневник решений** — каждое важное решение — карточка MEETING с тегом "decision"; через полгода агент находит контекст любого решения

### Нестандартные
- **Борд слушает совещание в реальном времени** — микрофон → Whisper транскрибирует live → карточки появляются прямо во время митинга; совещание закончилось — борд уже готов
- **Борд предсказывает квартал** — агент анализирует паттерны: какие идеи стали тикетами, сколько дней от IDEA до DONE, генерирует прогноз "enrichment-кластер станет PRD через 3 недели"
- **Военная комната конкурентной разведки** — агент сканирует App Store reviews конкурентов, changelog'и, вакансии (по стеку видно что строят), автоматически закидывает карточки в Inbox ночью
- **Борд с голосом** — говоришь "борд, идея" → терминал активируется, пишет под диктовку; руки заняты — мысли не теряются
- **Борд как онбординг** — новый PM открывает DONE, видит историю решений за год; нажимает карточку — агент объясняет контекст; онбординг без менторских сессий

### Безумные
- **Мультиагентный борд** — несколько агентов параллельно: один обогащает идеи, второй мониторит Jira на входящие, третий делает синтез каждую ночь; ты единственный человек в системе
- **Борд читает между строк** — агент анализирует тональность и частоту упоминаний тем в заметках, выявляет скрытые паттерны ("ты упоминаешь 'технический долг' каждые 3 дня — это сигнал")
- **Борд как второй мозг команды** — расшаренный vault для всей продуктовой команды; каждый PM пишет в свой Inbox, агент синтезирует пересечения и конфликты между командами
- **Временна́я машина продукта** — агент строит таймлайн эволюции идеи от первой заметки до релиза; визуализация "путь фичи" для любого тикета
- **Борд-оппонент** — при каждой новой идее агент автоматически генерирует devil's advocate: почему не стоит делать, какие риски, какие альтернативы; антипаттерн группового мышления
