# BL-161: Поиск и фильтрация отчётов — Requirements

## 1.1 Overview

Добавить на страницу `report.html` поиск по имени/заголовку отчёта и фильтрацию
по типу отчёта из YAML frontmatter. Сейчас список отчётов (~410 файлов) не имеет
инструментов навигации — пользователю приходится прокручивать всё вручную.

**Пользователь:** продакт-менеджер, использующий PM Assistant для работы со знаниями.

**Проблема:** при 410+ отчётах невозможно быстро найти нужный отчёт по названию
или отфильтровать, например, только протоколы встреч или еженедельные отчёты.

## 1.2 User Stories

```
US-01: Как PM, я хочу искать отчёт по названию или имени файла,
       чтобы быстро находить конкретный документ без ручной прокрутки.

US-02: Как PM, я хочу фильтровать отчёты по типу (daily, sync, synthesis и др.),
       чтобы видеть только релевантную категорию документов.

US-03: Как PM, я хочу комбинировать поиск и фильтр,
       чтобы найти, например, синтез за конкретный месяц.
```

## 1.3 User Flows

```
FLOW-01: Поиск отчёта
1. Пользователь открывает report.html → видит список отчётов с поисковой строкой вверху
2. Пользователь вводит текст в поисковую строку (например, "grafana" или "week-28")
3. Список фильтруется в реальном времени (debounce 200ms):
   → совпадение по title (case-insensitive) ИЛИ filename (case-insensitive)
   → MATCH: отображаются только совпавшие отчёты
   → NO MATCH: пустое состояние "Ничего не найдено"
4. Пользователь очищает строку (крестик или Backspace) → список возвращается к полному виду
   (с учётом активного фильтра по типу)

FLOW-02: Фильтрация по типу
1. Пользователь видит строку фильтр-чипов под поисковой строкой
2. Чипы: ALL + по одному для каждого типа, имеющего хотя бы 1 отчёт
   (с количеством в скобках, например "sync (132)")
3. По умолчанию выбран ALL
4. Пользователь кликает на чип "sync"
   → список показывает только отчёты с type=sync
   → чип "sync" подсвечен, остальные нет
5. Пользователь кликает на другой чип "daily"
   → выбор переключается на "daily" (single-select, не multi-select)
6. Пользователь кликает ALL → фильтр сбрасывается

FLOW-03: Комбинация поиск + фильтр
1. Пользователь выбирает чип "weekly-status-report" → видит 19 отчётов
2. Пользователь вводит "29" в поиск → видит отчёты недели 29
3. Оба фильтра применяются одновременно (AND)
```

## 1.4 Acceptance Criteria

```
AC-01 (US-01):
  GIVEN: страница report.html загружена, список отчётов отображается
  WHEN: пользователь вводит "supplier" в поисковую строку
  THEN: список содержит только отчёты, в title или filename которых
        есть подстрока "supplier" (case-insensitive)
        AND количество отфильтрованных отчётов отображается в заголовке списка

AC-02 (US-01):
  GIVEN: поисковая строка содержит текст
  WHEN: пользователь нажимает кнопку очистки (✕) или стирает текст
  THEN: список возвращается к полному виду (с учётом активного фильтра типа)

AC-03 (US-02):
  GIVEN: endpoint GET /api/v1/reports возвращает поле `type` для каждого отчёта
  WHEN: страница загружается
  THEN: фильтр-чипы генерируются динамически из уникальных значений type
        AND каждый чип показывает количество отчётов этого типа в скобках
        AND типы без отчётов не отображаются

AC-04 (US-02):
  GIVEN: выбран чип "sync"
  WHEN: пользователь кликает чип "daily"
  THEN: фильтр переключается на "daily" (single-select)
        AND список обновляется мгновенно

AC-05 (US-03):
  GIVEN: выбран чип "weekly-status-report" И в поисковой строке текст "29"
  WHEN: список фильтруется
  THEN: отображаются только отчёты, у которых type="weekly-status-report"
        И title или filename содержит "29"

AC-06 (US-01):
  GIVEN: поиск или фильтр не дал результатов
  WHEN: список пуст
  THEN: отображается сообщение "Ничего не найдено" вместо пустого пространства

AC-07 (US-02):
  GIVEN: отчёт не имеет поля type в frontmatter
  WHEN: список загружается
  THEN: отчёт получает type="other"
        AND чип "other" отображается, если есть хотя бы 1 такой отчёт
```

## 1.5 Out of Scope

- Полнотекстовый поиск по содержимому отчёта (только по title и filename)
- Multi-select фильтров (несколько типов одновременно)
- Сортировка отчётов (по дате, по имени) — отдельная задача
- Сохранение состояния фильтров между сессиями
- Серверная фильтрация (всё на клиенте, данные уже загружены)

## 1.6 Dependencies

- Endpoint `GET /api/v1/reports` — нужно добавить поле `type` в ответ
- Типизация отчётов: `wiki/concepts/pm_assistant-report-types.md` (C-0010)
- Vue 3, marked.js (уже подключены)
- `frontmatter_utils.read_frontmatter` или inline-парсинг YAML (бэкенд)
