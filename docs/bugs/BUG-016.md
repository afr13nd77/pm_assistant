# BUG-016 — patch_jira_links: exact match не патчит ключи с комментариями

**Severity:** major
**Компонент:** knowledge-engine
**Файл:** knowledge-engine/app/jira_key_sync.py, строка 271
**Обнаружен:** 18.06.2026
**Связь:** BL-134

## Observed behavior
Функция `patch_jira_links()` не заменяет Jira-ключи на wikilinks в протоколах, если после ключа есть комментарий.

Строка 271: `if line.strip() == plain:` — точное совпадение `- GO-153` не матчит реальные строки вида:
```
- GO-153 (списано/упомянуто в контексте задач)
- TMPL-42 (принципиально не уточнено, но упоминается как пример ID)
```

## Expected behavior
Ключи с комментариями должны патчиться:
```
- [[wiki/domains/search-engine/tasks/GO-153|GO-153]] (списано/упомянуто в контексте задач)
```

## Steps to reproduce
1. Запустить meeting_fetcher для обработки email-транскрипта
2. Claude генерирует протокол с комментариями после Jira-ключей
3. sync_jira_keys() корректно находит ключи и строит keys_map
4. patch_jira_links() не заменяет ни один ключ из-за exact match

## Root cause
`line.strip() == plain` (строка 271) требует точного совпадения всей строки с `- {key}`. Claude добавляет пояснения в скобках после ключей, поэтому совпадение никогда не срабатывает.

## Fix
Заменить exact match на startswith + word boundary. При замене сохранять trailing text.
