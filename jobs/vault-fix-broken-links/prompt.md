# Задача: исправить ошибочные wikilinks в vault

## Контекст

В Obsidian vault (путь: значение переменной `VAULT_PATH`, по умолчанию `E:/gitlab/Git/vault`) содержатся markdown-файлы с ошибочными wikilinks `[[target]]`. Эти ссылки были сгенерированы Claude при обработке заметок и указывают на несуществующие цели. Всего ~624 ссылки.

Файл с полным списком: `docs/health-scoring/broken_links.txt` (JSON, поле `broken_links` — массив объектов `{file, line, link, reason}`).

## Категории ошибочных ссылок и правила исправления

### Категория 1: `raw/inbound/*` (250 ссылок)
Ссылки на файлы в staging-директории raw/.
```
[[raw/inbound/tasks/2026-05-04-jira-SRCH-12345.md]]
[[raw/inbound/clippings/article.md]]
[[raw/inbound/ideas/draft-idea.md]]
```
**Действие:** удалить wikilink целиком (включая `[[` и `]]` и текст внутри). Обычно это отдельный пункт списка или строка — удалить всю строку, если она содержит только эту ссылку. Если ссылка внутри текста — удалить только `[[...]]`, оставить окружающий текст.

### Категория 2: `docs/meeting-protocols/*` (101 ссылка)
Ссылки на старый путь `docs/`, который не существует.
```
[[docs/meeting-protocols/2025-10-10-1500-конспект-встречи-«api-для-сервиса-sutochno]]
```
**Действие:** убрать `[[` и `]]`, оставить только отображаемое имя. Если есть pipe-синтаксис `[[target|display]]` — оставить display. Если нет — извлечь человекочитаемую часть: имя файла без пути и расширения, заменить дефисы на пробелы.

### Категория 3: bare `конспект-встречи` (132 ссылки)
Ссылки на протоколы встреч без пути — только имя файла.
```
[[2025-10-14-1446-конспект-встречи-«отели-сгруппированные»]]
```
**Действие:** убрать `[[` и `]]`, оставить текст как есть.

### Категория 4: bare `idea-*` (62 ссылки)
Ссылки на идеи без пути.
```
[[idea-dqi-pri-importe]]
[[idea-validaciya-obyazatelnyh-polej]]
```
**Действие:** убрать `[[` и `]]`, оставить текст.

### Категория 5: `Имя Фамилия` (14 ссылок)
Ссылки на людей (кириллица, формат «Имя Фамилия»).
```
[[Никита Терещенко]]
```
**Действие:** убрать `[[` и `]]`, оставить имя.

### Категория 6: `wiki/decisions/*` (5 ссылок)
Ссылки на несуществующий раздел wiki/decisions/.
```
[[wiki/decisions/log]]
```
**Действие:** убрать `[[` и `]]`, оставить текст.

### Категория 7: прочие (60 ссылок)
Разнородные ошибочные ссылки: относительные пути `../../`, ссылки на `input-IDEA-*`, `Projects/*`, `ideas/*`.
**Действие:** убрать `[[` и `]]`, оставить текст. Для pipe-синтаксиса — оставить display-часть.

## Алгоритм работы

1. Прочитай `docs/health-scoring/broken_links.txt` — получи массив `broken_links`.
2. Сгруппируй по полю `file` — чтобы обрабатывать каждый файл один раз.
3. Для каждого файла:
   a. Прочитай содержимое.
   b. Для каждой broken link из списка: найди `[[{link}]]` в тексте файла и замени:
      - Если **категория 1** (link начинается с `raw/inbound/`) И ссылка — единственный контент строки (строка = `- [[...]]` или `[[...]]`): **удали всю строку**.
      - Если **категория 1** и ссылка внутри текста: **удали `[[...]]` целиком**, оставь окружающий текст.
      - Для **всех остальных категорий**: замени `[[link]]` на просто `link` (без скобок). Если есть pipe `[[target|display]]` — замени на `display`.
   c. Запиши файл обратно.
4. Считай обработанные файлы и ссылки, выведи итоговую статистику.

## Важные правила

- **НЕ трогай** ссылки, которых нет в списке broken_links. В файлах есть рабочие wikilinks — их не менять.
- Все пути файлов в `broken_links` относительны от корня vault (например `wiki/daily-logs/file.md` = `{VAULT_PATH}/wiki/daily-logs/file.md`).
- Поле `link` содержит СОДЕРЖИМОЕ wikilink (без `[[` и `]]`). Ищи в файле `[[{link}]]` для точного совпадения.
- Файлы в кодировке UTF-8.
- После обработки выведи: количество обработанных файлов, количество исправленных ссылок, количество ссылок, которые не удалось найти (link не найден в файле — возможно уже исправлен или строка изменилась).

## Путь к vault

Используй переменную окружения `VAULT_PATH`. Если не задана — `E:/gitlab/Git/vault`.
